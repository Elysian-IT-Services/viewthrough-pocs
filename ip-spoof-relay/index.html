IP spoof relay (abandoned, does not work)

Pinned to — the operator switcher does not apply here, because this abandoned POC is the only one that sends that operator's bta and placement id.

This POC asked our own server to call the affiliate /visit/ link on the reader's behalf, sending the reader's IP address in X-Forwarded-For and Client-IP headers and copying their User-Agent, so the visit would look like it came from the reader. It cannot work and the approach was dropped. Those headers are just text in the request: the TCP connection still comes from our server's IP, and the affiliate's redirect comes back to Node and dies there, so the reader's browser never follows it and never receives an operator cookie.

The code is kept here on purpose, forged headers and all, so you can see what was tried and why it was abandoned. Nothing links to this page and nothing runs until you press the button.

How to test

  1. Press Run the abandoned relay once. The panel below fills in with whatever the server got back.
  2. Read operatorLocation in that panel. That is the redirect the affiliate sent, sitting in our JSON as plain text — the browser never went there, which is the whole failure.
  3. Open DevTools, go to Application, then Cookies, and look for anything from . Expect none: the server received the response, not the browser.
  4. Look at the terminal running the server. It prints the IP it forwarded. On a local run that is ::1, which tells the affiliate nothing about the reader.
  5. Note that success: true is written by our own code for any status from 200 to 399. It is not the operator confirming attribution.
