Pop-over (corner window)

Simulated lander. Accepting consent opens the affiliate link in a window in the bottom-right corner. It loads top-level and closes itself once the redirect, the landing page and the operator's own beacon have had time to run.

Same attribution as the pop-under, a different interruption. The corner window is a real top-level page and not a frame, so writes its first-party exactly as it would in a normal tab. It does appear in front — no browser lets a page send a window it just opened behind itself — but at in the corner that is a small window appearing, not a full-screen takeover. On phones the size is ignored and you get a full tab, so this is a desktop improvement only.

Verify

  1. A small window opens in the bottom-right and closes itself; the status log goes fired → waiting → closed, and the closing line prints exactly how many ms the window was alive.
  2. Before it closes, in that window: Network → 301 from → → 200, top-level. Application → Cookies → : first-party .
  3. Note what the lander did while that happened: did focus come back to you, and was the corner window small enough to ignore? That is the whole point of this variant.
  4. Status says still-open → the browser refused to close the window; close it yourself and note which browser. Status says blocked → window.open was refused (expected in Meta's in-app browser) and the explicit click-through still works.
  5. The decisive test: let it close, then complete a test registration and confirm it still attributes in — i.e. closing the window did not drop the credit.

Finding the shortest delay that still attributes

A page cannot see a cross-origin window finish loading, so the delay is the one number that has to be found by hand. It takes one sitting, here on this page:

  1. Set the delay to 0, press Reset, accept consent. The window stays open.
  2. In that window open DevTools → Application → Cookies → and watch for . Its Network tab gives you the same answer: the row for finishing is the moment attribution is recorded.
  3. Compare that against the fired timestamp in the status log below. The gap is your floor.
  4. Put the floor plus a small margin in the box, press Reset, run again, and confirm the cookie is present before the window closes. Halve the margin and repeat until it stops working — the last value that worked is the answer.
  5. Put that number in POPUP_CLOSE_AFTER_OPEN_MS in core/constants/index.js so every run starts there, then redo it once on a throttled connection. The floor on Fast 3G is not the floor on your desk.
