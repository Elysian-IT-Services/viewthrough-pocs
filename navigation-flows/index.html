Navigation flows

This POC tests the two original ways of sending a reader through the affiliate link without losing them: A, the reverse pop-under, which opens a fresh copy of the publisher page in a new tab and sends the old tab off to the affiliate, and C, a 400 by 300 popup, which keeps the reader here and loads the affiliate in a small window. Both deliver a real top-level load, so the operator can set its own cookies, but both still count as a click journey, so neither proves view-through attribution. These two flows are the ancestors of the pop-under and reverse pop-under POCs in this repo.

How to test

  1. Use a fresh browser profile so no earlier referral state is lying around, and leave the normal browser protections on.
  2. Set the close delay to 0, then press A: Reverse pop-under. Expect this tab to go to the affiliate link and a new publisher tab to appear in front of it.
  3. Come back here, set the delay to 0 again and press C: 400 by 300 popup. Expect a small window on the affiliate link while this page stays put.
  4. In the opened window's DevTools, Network tab, find the operator's token POST, not just the first /visit/ redirect, and check Application then Cookies for a first-party cookie on the operator's domain.
  5. Copy the AFP from the log below and look for it against a test registration in affiliate reporting. A page that loaded is not credit.
  6. Repeat with the delay set to 3 and count the real windows afterwards. The log says unverified whenever the page cannot prove what happened, which is most of the time.

seconds. Use 0 to leave the window open and read the Network tab.
