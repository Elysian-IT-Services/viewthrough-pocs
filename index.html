Attribution POCs

Every approach we tried for crediting an affiliate without sending the reader away. Each page has its own short test steps, and the bar at the top of each one switches operator. Outbound links are tagged vtpoc-test-001 so POC traffic is never mistaken for real clicks.

Current approaches

  • Cookie proof — the same affiliate link opened top-level and in an iframe, so you can compare the cookies each one keeps.
  • Pop-under — your lander moves to a new tab and this tab goes to the affiliate link behind it, so the operator loads out of sight. The one that works everywhere.
  • Pop-over — the affiliate link opens in a small corner window that closes itself. The reader stays on the lander.
  • Server-side click — the server calls the affiliate link, then the browser loads the URL it minted.
  • Hidden iframe — the affiliate link loads in an iframe on the lander and the user stays put. Needs an operator cookie change to work.
  • Browser extension — an installed extension fires the affiliate click from outside the page.

Earlier attempts, now set aside

  • Banner impression — load the operator's real creative and hope the impression alone earns credit.
  • Navigation flows — the first versions of the two pop-under ideas, with tests.
  • IP spoof relay — abandoned, but still runnable. The server forged the reader's IP and user agent. Run it and watch it fail, so nobody tries this again.

Browser behaviour we had to understand first

  • Opener isolation — what a new tab can still do to the page that opened it.
  • User gesture — how long a click stays valid for opening a window.
  • Pre-navigation beacon — finishing a tracking request as the page unloads.
  • SameSite cookies — which cookie attributes the browser actually stores.
