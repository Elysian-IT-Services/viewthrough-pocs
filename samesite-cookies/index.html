SameSite cookies

This POC asks our own server to set a cookie under SameSite=Strict, Lax and None in turn, so you can see exactly which attributes end up on the stored cookie. It works, but read the result carefully: these requests go to our own origin, so they are same-site and all three policies are accepted. It does not prove anything about the cross-site case, which is the one that actually breaks attribution — for that, see the banner impression POC, where the operator's cookie is rejected on a cross-site response.

How to test

  1. Open DevTools, go to Application, then Cookies, then the entry for this origin, and delete anything named tracking_id so you start clean.
  2. Press each of the three buttons in turn, re-reading the cookie list after each. Expect tracking_id to be stored every time, with the SameSite column changing to match the button.
  3. Look at the None result specifically. It only stores because browsers treat localhost as secure; on a plain http host that cookie would be dropped for missing Secure.
  4. Compare with the banner impression POC, where the same kind of cookie arrives on a cross-site response and the browser refuses it.
