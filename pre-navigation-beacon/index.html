Pre-navigation beacon

This POC tests whether a tracking request can finish after the reader has already left the page. It worked: navigator.sendBeacon hands the request to the browser, which delivers it in the background even though this page is unloading, so the link does not have to be delayed, intercepted or hidden behind a fake loading screen. It solves delivery only — the request arriving says nothing about the operator crediting anything.

How to test

  1. This page needs POST /api/track-beacon on the server. If that route is missing the beacon will show as failed in step 4.
  2. Open DevTools, go to the Network tab and tick Preserve log, or the record clears the moment you navigate and you will see nothing.
  3. Press Leave this page. Expect the browser to go to example.com immediately, with no pause.
  4. Come back and read the preserved Network log. Expect a track-beacon request of type ping with status 204, sent at the same moment as the navigation.
  5. Check the terminal running the server. Expect it to have printed the beacon body.
